## Talking with PILOT

`pilot_talking` · beginner · 3 checkpoints

Print text and compute values with PILOT's one-letter commands.

### Learning objectives

- Print a line of text with T:
- Print several lines in order
- Compute a value with C: and print it

### Teacher notes

PILOT has no line numbers and no syntax beyond LETTER: text, which makes it the gentlest place to start. Every unit ends with a colon, and forgetting it is the only error a beginner tends to make here.

### Checkpoints

#### 1. Say hello

Use a T: unit to display exactly: Hello, World!

Handout file: `pilot_talking-1.pilot` · checked by prints: Hello, World!

Starting point:

```text
T: Hello
```

Worked answer:

```text
T: Hello, World!
```

Hints, in the order a learner should see them:

1. T: prints everything after the colon.
2. Punctuation is printed as written, comma and all: T: Hello, World!

#### 2. Two lines

Print One on the first line and Two on the second.

Handout file: `pilot_talking-2.pilot` · checked by prints: One / Two

Starting point:

```text
T: One
```

Worked answer:

```text
T: One
T: Two
```

Hints, in the order a learner should see them:

1. Each T: unit prints one line.
2. Add a second unit underneath: T: Two

#### 3. Compute, then print

X is computed for you. Print its value.

Handout file: `pilot_talking-3.pilot` · checked by prints: 42

Starting point:

```text
C:X = 6 * 7
T: The answer is
```

Worked answer:

```text
C:X = 6 * 7
T: $X
```

Hints, in the order a learner should see them:

1. C:X = ... stores a value in X.
2. A $ in a T: unit is replaced by the variable's value: T: $X

## Labels, Jumps and Subroutines in PILOT

`pilot_flow` · intermediate · 3 checkpoints

Send the program somewhere else with J: and U:, and stop it with E:.

### Learning objectives

- Skip lines with J:
- Reuse a block of units with U: and return from it with E:
- Stop a program early with E:

### Teacher notes

PILOT's control flow is the whole of the language, and it is where learners first see that a program is a sequence the machine can move around in. The classic mistake is forgetting the final E: in a subroutine, which runs the rest of the program twice.

### Checkpoints

#### 1. Jump over a line

The program must print Landed and never print Not reached.

Handout file: `pilot_flow-1.pilot` · checked by prints: Landed

Starting point:

```text
T: Not reached
E:
*SKIP
T: Landed
```

Worked answer:

```text
J: SKIP
T: Not reached
E:
*SKIP
T: Landed
```

Hints, in the order a learner should see them:

1. J: SKIP jumps to the line labelled \*SKIP.
2. Put J: SKIP at the top, so the line that prints Not reached is never reached.

#### 2. Call a subroutine

Print Inside, then return and print Back.

Handout file: `pilot_flow-2.pilot` · checked by prints: Inside / Back

Starting point:

```text
U: *SUB
T: Back
E:
*SUB
T: Inside
```

Worked answer:

```text
U: *SUB
T: Back
E:
*SUB
T: Inside
E:
```

Hints, in the order a learner should see them:

1. U: jumps to a label and remembers where to come back to.
2. The subroutine must end with E: so the program returns instead of running on.

#### 3. Stop early

Print Before and stop. After must never appear.

Handout file: `pilot_flow-3.pilot` · checked by prints: Before

Starting point:

```text
T: Before
T: After
```

Worked answer:

```text
T: Before
E:
T: After
```

Hints, in the order a learner should see them:

1. E: ends the program when it is not inside a subroutine.
2. Put an E: unit between the two T: units.
