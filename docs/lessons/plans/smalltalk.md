## Objects and Messages in Smalltalk

`smalltalk_messages` · beginner · 3 checkpoints

There are no statements - everything is a message to an object.

### Learning objectives

- Send a unary message to an object
- Write to the Transcript
- Put several messages in a cascade

### Teacher notes

The change of mind needed here is bigger than the syntax: 6 \* 7 is not an expression that multiplies, it is the object 6 being sent the message \*. Point that out before the first checkpoint or the language will feel arbitrary.

### Checkpoints

#### 1. Send a message

Make the program answer 42.

Handout file: `smalltalk_messages-1.st` · checked by prints: 42

Starting point:

```smalltalk
6 * 6
```

Worked answer:

```smalltalk
6 * 7
```

Hints, in the order a learner should see them:

1. The last value in a block of code is shown.
2. 6 \* 7 answers 42.

#### 2. Print a line

Print Hello, World! to the Transcript.

Handout file: `smalltalk_messages-2.st` · checked by prints: Hello, World!

Starting point:

```smalltalk
Transcript show: 'Hello'
```

Worked answer:

```smalltalk
Transcript show: 'Hello, World!'; cr
```

Hints, in the order a learner should see them:

1. Transcript is the object you write to.
2. show: takes the text; cr finishes the line.

#### 3. Ask a string how long it is

Make the program answer 5.

Handout file: `smalltalk_messages-3.st` · checked by prints: 5

Starting point:

```smalltalk
'hello'
```

Worked answer:

```smalltalk
'hello' size
```

Hints, in the order a learner should see them:

1. Strings answer messages about themselves.
2. size answers how many characters there are.

## Classes and Blocks in Smalltalk

`smalltalk_classes` · intermediate · 3 checkpoints

Define a class, give it a method, and use a block.

### Learning objectives

- Read a class definition as a message
- Add a method to a class
- Run a block with value

### Teacher notes

A definition reports itself: the class definition answers Counter, and each method definition answers its own header, so those lines appear in the output. That is the workspace's print-it rule rather than noise, and saying so stops the first checkpoint looking broken.

### Checkpoints

#### 1. Add a method

Counter needs a way to answer its count. Add one and use it.

Handout file: `smalltalk_classes-1.st` · checked by prints: Counter / Counter >> initialize / Counter >> value / 0

Starting point:

```smalltalk
Object subclass: #Counter
  instanceVariableNames: 'count'

Counter >> initialize
  count := 0

| c |
c := Counter new.
c value
```

Worked answer:

```smalltalk
Object subclass: #Counter
  instanceVariableNames: 'count'

Counter >> initialize
  count := 0

Counter >> value
  ^count

| c |
c := Counter new.
c value
```

Hints, in the order a learner should see them:

1. A method is a header, then an indented body.
2. Answer the count with ^count.

#### 2. Run a block

Double 21 by running a block.

Handout file: `smalltalk_classes-2.st` · checked by prints: 42

Starting point:

```smalltalk
[ :x | x * 1 ] value: 21
```

Worked answer:

```smalltalk
[ :x | x * 2 ] value: 21
```

Hints, in the order a learner should see them:

1. A block between square brackets is run with value:.
2. The block multiplies by the wrong number.

#### 3. Add up a range

Add the numbers 1 to 5 with inject:into:.

Handout file: `smalltalk_classes-3.st` · checked by prints: 15

Starting point:

```smalltalk
(1 to: 5) inject: 0 into: [ :sum :each | sum + 1 ]
```

Worked answer:

```smalltalk
(1 to: 5) inject: 0 into: [ :sum :each | sum + each ]
```

Hints, in the order a learner should see them:

1. inject:into: carries a running value through the block.
2. Add each, not 1: sum + each
